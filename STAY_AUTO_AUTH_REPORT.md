# Автоматический вход через Stay for Safari

Дата: 27.10.2026. Целевая площадка: `https://fork995.github.io/Test2/`. Стабильный репозиторий AppTest- не изменялся.

## Как работает интеграция

Один userscript выполняется только на двух разрешённых адресах. На оригинальном CleverVet он ищет Auth0-запись `@@auth0spajs@@`, ключ которой относится к `api.clevervet.tech`, читает `body.access_token` и обязательный `expiresAt`, а при наличии JWT `exp` выбирает более ранний срок. Просроченный или истекающий менее чем через 15 секунд токен в GM-хранилище не записывается.

В GM-хранилище создаётся одноразовая запись версии 1 с токеном, временем получения и сроком действия. Запись принимается Test2 не позднее трёх минут после создания. Userscript Test2 ждёт сигнал готовности приложения, ставит краткоживущую метку захвата для защиты от двух вкладок, удаляет GM-запись и только затем передаёт данные в память страницы через `CustomEvent`.

Приложение независимо проверяет формат, свежесть и срок записи. Затем оно вызывает тот же `createSessionApi` и тот же `GET /branches`, которые используются ручным и clipboard-входом. Только HTTP 200 создаёт рабочий сеанс и открывает «Пациенты». При 401/403, ошибке сети или неверных данных обычный экран ручного входа остаётся доступен.

Токен не передаётся через URL, DOM, console, аналитику или внешний сервис. В Test2 он хранится только в памяти существующего API-клиента. `?importAuth=1` продолжает работать: если Stay передал токен первым, параметр удаляется существующим `history.replaceState`; если Stay недоступен, остаётся прежняя кнопка импорта из буфера.

## Установка на iPhone

1. Откройте Stay и создайте новый userscript.
2. Удалите шаблонный текст и полностью вставьте содержимое файла `stay/clevervet-mobile-stay.user.js`.
3. Сохраните и включите скрипт. У него должны остаться только два `@match`: оригинальный CleverVet и `/Test2/*`.
4. В iOS откройте «Настройки → Safari → Расширения → Stay», включите расширение и разрешите доступ к `www.app.clevervet.tech` и `fork995.github.io`.
5. Откройте оригинальный CleverVet в Safari и дождитесь появления авторизованного интерфейса.
6. В течение трёх минут откройте `https://fork995.github.io/Test2/`. Если мост Stay работает, приложение само проверит токен и откроет пациентов.
7. Если появился обычный экран входа, обновите оригинальный CleverVet, затем снова откройте Test2. Ручной ввод и `?importAuth=1` остаются резервными способами.

Не вставляйте реальный токен в редактор Stay, исходники, GitHub или сообщения. Userscript самостоятельно читает Auth0-кеш только на оригинальном домене.

## Проверки

Автоматические тесты используют только синтетические JWT и mock API. Они проверяют действующий и просроченный токен, отсутствие токена/Stay, обязательную проверку API, 401/403, сетевую ошибку, очистку GM-хранилища, конкуренцию двух вкладок, одноразовую попытку, совместимость с `?importAuth=1`, ручной вход и более ранний срок `expiresAt` из Auth0.

Ни один автоматический тест не обращается к реальному CleverVet и не выполняет операции записи.

Результаты локальной проверки:

- TypeScript: без ошибок;
- Vitest: **41 файл, 854 теста — пройдены**;
- production-сборка Vite и проверка трёх локальных asset-файлов: успешно;
- smoke-тест production на ширинах 375, 390 и 430 px: одна Stay-передача, автоматическое открытие «Пациентов», два mock GET, 0 запросов записи, 0 необработанных ошибок и 0 горизонтальных переполнений.

## Неподтверждённые ограничения Safari и Stay

- Практическая передача реального токена через GM-хранилище и `CustomEvent` между sandbox Stay и Test2 ещё должна быть проверена на iPhone.
- Поддержка `GM_deleteValue` в установленной версии Stay отдельно не подтверждена. Userscript имеет безопасный fallback: записывает `null`, который Test2 не принимает как авторизацию.
- GM API не предоставляет подтверждённой атомарной транзакции. Краткая метка захвата проверена на моках и позволяет только одной из двух одновременных вкладок получить запись, но реальное планирование вкладок Safari может отличаться.
- После успешной передачи временная GM-запись удаляется. Новый полностью перезагруженный Test2 не хранит прежний токен; для нового сеанса нужно снова открыть или обновить оригинальный CleverVet, чтобы userscript создал свежую запись.
- Safari может приостанавливать userscript и таймеры фоновой вкладки. Для первичной проверки оригинальный CleverVet следует оставить активным до записи, затем открыть Test2.
- Refresh token в подтверждённом Auth0-кеше отсутствует. Userscript не обновляет access token и не обещает фоновое продление Auth0-сеанса.

До практической проверки на iPhone автоматический вход считается тестовой функцией Test2.
