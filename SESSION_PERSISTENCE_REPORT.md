# Сохранение и восстановление авторизации Test2

Дата: 27.10.2026. Область изменений: только `fork995/Test2`; стабильный `AppTest-` не изменялся.

## Причина потери авторизации

`App.tsx` хранил токен только внутри API-клиента и синхронно вызывал `logout()` на событии `pagehide`. Safari отправляет `pagehide` при закрытии, выгрузке и помещении страницы в bfcache, поэтому любой из этих сценариев закрывал API-клиент и удалял сеанс из памяти.

## Реализация

Модуль `app/src/authSession.ts` управляет одной записью `clevervet.mobile.auth-session.v1` в `localStorage` origin Test2. Запись содержит только:

- `version: 1`;
- `accessToken`;
- `expiresAt` или `null`, если срок отсутствует в подтверждённых данных.

Пароль, refresh token, Auth0-профиль, S3-ключи, пациенты и медицинские данные не сохраняются. Если JWT содержит корректный `exp`, эффективный срок ограничивается более ранним значением между `exp` и сроком Stay. Декодирование `exp` используется только как предварительная проверка; каждое восстановление подтверждается существующим `GET /branches` через `createSessionApi`.

При запуске приложение показывает состояние «Восстановление сессии» и не мигает экраном входа. HTTP 200 открывает «Пациенты». HTTP 401 удаляет запись. HTTP 403 и временная ошибка сети сохраняют потенциально действующий токен и показывают кнопку повторной проверки. Бесконечных повторов нет.

Событие `storage` синхронизирует явный выход между вкладками. Закрытие, обновление, bfcache и фоновая выгрузка вкладки запись не удаляют. Если Safari запрещает `localStorage`, текущая вкладка продолжает работать и показывает предупреждение о невозможности восстановления после закрытия.

## Безопасность

В `index.html` нет внешних скриптов; CSP оставляет `script-src 'self'` и разрешает сетевые подключения только приложению и API CleverVet. Токен не помещается в URL, DOM, console, аналитику или сообщения об ошибках. Хранение в `localStorage` не равно защите HttpOnly-cookie: JavaScript того же origin имеет доступ к записи. Это осознанное ограничение тестовой версии Test2.

## Совместимость

Первичный вход Stay, ручной вход и `?importAuth=1` используют прежнюю проверку API. Проверенный токен из любого реального способа входа сохраняется единым модулем. Демо-сессия не сохраняется. Userscript Stay менять не требуется.

## Проверки

Автоматические тесты используют синтетические токены и mock API. Они охватывают сохранение после Stay, закрытие/перезагрузку, восстановление, истечение, неизвестный и повреждённый JWT, повреждённый и недоступный `localStorage`, сеть, 401, 403, явный и межвкладочный выход, новый Stay-токен, гонку восстановления, ручной вход и отсутствие токена в URL/ошибках.

Реальный access token и реальные данные CleverVet в тестах не использовались.

Результаты локальной проверки:

- TypeScript и production-сборка Vite: успешно;
- Vitest: **43 файла, 868 тестов — пройдены**;
- mobile smoke на 375, 390 и 430 px: вход Stay и последующее восстановление после reload без второй Stay-передачи; 0 запросов записи, 0 необработанных ошибок, 0 горизонтальных переполнений.

## Ограничения Safari

- В приватном режиме или при ограничениях хранилища Safari может запретить запись в `localStorage`; приложение остаётся работоспособным только до закрытия вкладки.
- iOS может приостанавливать таймер истечения в фоне. При возврате API всё равно проверяет токен; 401 очищает сессию.
- Без refresh token приложение не продлевает Auth0-сеанс. После фактического истечения нужно открыть оригинальный CleverVet, чтобы Stay передал новый access token.
